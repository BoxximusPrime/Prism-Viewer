# Light and reflection probe markers

Status: in progress; uncommitted. Release build and XML/resource staging checks passed. In-world verification pending.

Build > Options contains two independent, persistent, default-off toggles:

- **Show Light Source Icons**: yellow bulb markers for prims with Light enabled.
- **Show Reflection Probe Icons**: sphere markers for explicit reflection probe prims.

Markers appear at their source prim, show through surrounding geometry, and stay
32 UI pixels tall. They are limited to 128 meters and the camera draw distance.
HUD attachments are excluded. Automatically generated renderer probes have no
editable prim and do not get markers. If a prim is both a light and a probe, the
probe marker takes precedence when both toggles are enabled.

A plain click selects exactly that prim. For a linked prim (including a light or
probe on the root), Edit linked is enabled. Standalone objects select normally.
Existing selection filters and permissions still apply. Shift/Ctrl use normal
selection extension behavior. Script-error icons retain their debug action.

Markers disappear when their toggle is disabled, the source is deleted, or the
source ceases to be a light/probe. New sources are discovered within 250 ms.
The light bulb is a generated transparent asset; the probe sphere reuses the
existing Object_Sphere asset.

## In-world verification checklist

1. Toggle each option independently, then together; verify settings survive restart.
2. Click a standalone light and probe in normal click mode and in the build tools, including Select Face mode.
3. Link a light/probe as a child: clicking must select only that child, with Edit linked enabled.
4. Repeat for a light/probe on the root of a linkset; siblings must not be selected.
5. Put the source inside opaque geometry: the visible marker must remain clickable.
6. Move the source and camera; verify alignment, constant size, nearest overlapping
   marker selection, screen-edge behavior, and the distance cutoff.
7. Disable Light/probe on the source, delete it, cross regions, and toggle off;
   check for stale markers. Verify script-error icons still open script debug.
8. Check Select Only My Objects/Movable Objects, Shift/Ctrl extension, and a prim
   that has both light and probe flags.

## Projector lights without shadows

Put `[no-shadow]` anywhere in the **emitting prim's description**, for example:

    Ceiling spotlight [no-shadow]

The tag is case-insensitive. It preserves the projected texture, color, intensity,
beam, and light range, but disables shadows generated by that projector. It also
releases the source's projector-shadow slot for another light. It does not prevent
the prim's geometry from casting a shadow under the sun or another light.

For a child light, enable Edit linked and edit that child's description (the icon
can select it). A tag on the root does not automatically apply to its children.
Remove the tag to restore normal shadow eligibility. Your description edits take
effect locally immediately; descriptions from scripts/other viewers are fetched
for active projectors about once a minute, with the shared request queue limited
to ten requests per second. Initial lighting uses the cached/default behavior
until the description arrives.

The description is stored normally by Second Life. Only viewers implementing this
convention honor it. No new simulator flags are used.

Validation: `python scripts/tests/test_no_shadow.py` compiles and exercises the
production description parser, refresh scheduling, shadow binding, nomination,
and slot-release logic. In-world checks still needed: texture remains projected
on opaque and transparent surfaces; tag add/remove on standalone/linked lights;
relogin discovery; script edits; and metadata loading with SSS disabled.
